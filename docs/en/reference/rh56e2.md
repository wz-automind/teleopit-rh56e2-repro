# Inspire RH56E2 reference

## Supported surface

The integration supports one left hand, one right hand, or a dual-hand pair in
MuJoCo and over Modbus TCP. The hand is represented as six actuators driving a
12-joint kinematic model. PICO continuous hand pose and controller-gripper modes
are available through Teleopit's hand worker.

## Six-channel order

Every hardware vector uses this fixed order:

| Index | Channel | somehand actuated joint |
| ---: | --- | --- |
| 0 | Pinky | `pinky_proximal_joint` |
| 1 | Ring | `ring_proximal_joint` |
| 2 | Middle | `middle_proximal_joint` |
| 3 | Index | `index_proximal_joint` |
| 4 | Thumb bend | `thumb_proximal_pitch_joint` |
| 5 | Thumb rotation | `thumb_proximal_yaw_joint` |

Raw position `0` is treated as closed and `1000` as open. The value `-1` is
encoded as `0xFFFF` for the firmware's hold/no-change command. Model joint
ranges and direction must be physically checked against each hand before
continuous control.

## Modbus TCP register surface

| Purpose | Decimal | Hex | Function |
| --- | ---: | ---: | --- |
| Target angle | 1486 | `0x05CE` | FC16 write, 6 registers |
| Target speed | 1522 | `0x05F2` | FC16 write, 6 registers |
| Actual angle | 1546 | `0x060A` | FC03 read, 6 registers |
| Actual force | 1582 | `0x062E` | FC03 read, 6 registers |
| Actual current | 1594 | `0x063A` | FC03 read, 6 registers |
| Fault | 1606 | `0x0646` | FC03 read, 3 registers / 6 bytes |
| State | 1612 | `0x064C` | FC03 read, 3 registers / 6 bytes |
| Temperature | 1618 | `0x0652` | FC03 read, 3 registers / 6 bytes |

The default endpoint is `192.168.11.210:6000` with Unit ID `255` (`0xFF`).
Many hands may ship with the same default address. Configure and test one hand
at a time, assign unique addresses, and never attach two identical endpoints to
the same subnet.

```text
overlay/teleopit/sim2real/hands/rh56e2_protocol.py

overlay/teleopit/configs/pico4_sim2real_rh56e2.yaml
overlay/teleopit/configs/pico4_sim_rh56e2.yaml
overlay/teleopit/configs/robot/g1_rh56e2.yaml
overlay/assets/robots/unitree_g1/g1_29dof_rh56e2.xml
overlay/third_party/somehand/configs/retargeting/{left,right,bihand}/
overlay/third_party/somehand/assets/mjcf/inspire_rh56e2_{left,right}/
```

The somehand model converts 21 landmarks to joint radians. Teleopit selects the
six actuated joints and maps radians to the hardware range. The hardware driver
does not run a second pico-bridge receiver.

## Configuration

The real-hardware configuration uses:

```yaml
hands:
  enabled: true
  driver: rh56e2_modbus_tcp
  mode: vr_hand_pose
  sides: [left, right]
  rate_hz: 30.0
  frame_timeout_s: 0.25
  rh56e2:
    left_host: 192.168.11.210
    right_host: 192.168.11.211
    port: 6000
    unit_id: 255
    write_enabled: false
    max_temperature_c: 70
    open_on_failure: false
    open_on_shutdown: false
```

Keep `write_enabled: false` during installation, network setup, and telemetry
checks. `scripts/run/run_sim2real_rh56e2.sh` is the supported gated path that
turns it on after both real-control environment confirmations are present.

## Staged verification

1. Run offline validation with no hardware.
2. Run the dual-hand MuJoCo simulation and verify side/direction mapping.
3. Connect one unloaded hand and run read-only telemetry.
4. Use the guarded bench tool on one DOF with a small delta.
5. Repeat for the second hand, then run dual-hand read-only telemetry.
6. Validate G1 dry-run and standalone standing independently.
7. Run combined control only with an emergency-stop operator and clear area.

Exact commands and stop criteria are in the [complete usage guide](../usage.md).

## Safety behavior and limits

- Writes default to disabled in both code and YAML.
- A nonzero fault byte or temperature above the configured limit blocks writes.
- Stale/missing tracking holds each channel rather than inventing a pose.
- Minimum-change and rate gates reduce duplicate traffic; they are not safety-rated limiters.
- `open_on_failure` and `open_on_shutdown` default to false because an automatic release may be unsafe for a payload.
- The implementation has source-level test coverage, not certification for a particular hand, firmware, power supply, payload, or workcell.
