# RH56E2 真机控制检查

## 审查结论

截至 2026-09-20，代码已经具备 **静态兼容** 和 **只读联机预检** 条件，但尚不能标记为“真机已验证”。原因是没有在用户的 G1、两只 RH56E2、供电、网络和急停条件下完成实物测试。

| 检查项 | 结论 | 证据/剩余工作 |
|---|---|---|
| 六自由度顺序 | 符合 | 仿真、手册和 Unitree `xr_teleoperate` 均为小指、无名指、中指、食指、拇指弯曲、拇指旋转 |
| somehand 输出范围 | 符合 | 四指 0–1.7 rad、拇指弯曲 0–0.5 rad、旋转 -0.1–1.3 rad；按 Unitree 公式映射为 0–1000 |
| RH56E2 通信 | 代码符合手册 | 实现 Modbus TCP FC03/FC16、端口 6000、角度目标 1486、实际角度 1546 等；需实机确认 unit ID 和固件响应 |
| 双手网络 | 有保护 | 代码拒绝相同 IP:port；仍需先单独修改一只手的出厂 IP |
| G1 身体控制 | 复用上游 | 使用 Teleopit v0.5.0 的 G1 bridge、50 Hz policy 和 200 Hz DDS/PD 路径；需完成站立架与急停验收 |
| 电气 | 参数已核对 | 单手 24 V、静态约 0.2 A、空载平均约 1.2 A、最大抓取约 4.5 A；线束、接地和电源容量必须现场确认 |
| 故障与温度 | 软件门控已实现 | 六路故障非零或温度高于 70°C 时拒绝写；阈值是软件保守值，不替代厂家限制 |
| 端到端真机 | 未验证 | 需要按下列 A–E 阶段记录实测结果 |

## 代码请求流

### 身体链路

```text
PICO 4 身体姿态
  -> pico-bridge 网络帧
  -> Teleopit PICO worker（最高 120 Hz 轮询）
  -> 人体到 G1 参考姿态重定向/缓冲
  -> G1 policy（50 Hz）
  -> 安全管理器：状态机、关节位置/速度、Kp 渐升
  -> g1_bridge_sdk / DDS PD 控制（200 Hz）
  -> G1 29 个本体关节
```

这里的 120/50/200 Hz 是各环节更新频率，不是端到端延迟。真实延迟还包含 PICO 采集、Wi-Fi、调度、推理和 DDS 执行，必须实测时间戳。

### 手部链路

```text
PICO 4 左右手 26 关节点
  -> Teleopit hand snapshot
  -> pico_hand_to_landmarks 转为 somehand 21 点定义
  -> somehand 左右手 SLSQP 重定向（配置 60 Hz）
  -> 选取 6 个 RH56E2 主动关节弧度
  -> Unitree Inspire 公式 (max - q) / (max - min)
  -> 六路 0–1000 目标
  -> RH56E2 Modbus TCP FC16，寄存器 1486
  -> 左右手各 6 个执行器
```

状态反馈另走 FC03：角度 1546、力 1582、电流 1594、故障 1606、状态 1612、温度 1618。控制发送上限默认 30 Hz，健康状态默认每 0.5 秒刷新；它们同样不是网络延迟指标。

## 与 `xr_teleoperate` 的关系

Unitree 官方仓库里的 Inspire 控制器使用 G1/Unitree 侧 DDS 服务（DFX/FTP topic 和 `inspire_sdkpy`），而本项目按 E2 手册直接连接手的 Modbus TCP 端口。两者不能把通信后端直接互换，但以下部分可以用于交叉检查：

- 六路硬件顺序相同；
- Inspire 目标定义为 0 关闭、1 打开；
- 四指、拇指弯曲和拇指旋转的弧度范围相同；
- Unitree 的归一化公式与本项目 `radians_to_raw()` 一致。

因此，现有 E2 模型和重定向顺序符合要求；真正缺失的原本是直接 Modbus 真机后端，本次已补齐代码，但仍要通过实机验收。

## 安全验收步骤

### A. 断电检查

- 核对左右手型号、固件、连接器针脚和线束，确认 24 V 与 GND 极性。
- 电源按两手同时峰值留裕量；两手理论峰值合计 9 A，不计启动和其他负载余量。
- 确认保护接地、屏蔽双绞线、保险/限流和可触达的断电装置。
- 手和 G1 固定牢靠，运动范围内无人、无易碎物。

### B. 单手只读

一次只接一只手，以默认 `192.168.11.210:6000` 运行预检。记录：

- 六路实际角度是否在 0–1000；
- 六路故障是否全 0；
- 温度、电流是否合理；
- 多次连接是否稳定。

此阶段不得设置 `write_enabled=true`。

### C. 单手低速点动

将手放在独立台架上，以低速度和低力阈值逐轴测试 1000、750、500、250、0。特别确认拇指旋转方向和机械开/闭定义；如实机方向与配置不一致，应修改映射配置，不得靠机械限位硬顶。

验收：每轴方向正确、无卡滞、无过流/过温、反馈连续，断网后行为可控。

### D. 双手联机

- 给左右手设置不同 IP，分别断电重启后验证地址保持。
- 同时运行只读预检，确认数据没有串手。
- 低速运行相同开合动作，确认左右语义一致。
- 人为中断 PICO 手跟踪，确认驱动发送 `-1` 保持而不是继续旧轨迹。

### E. G1 整机

- 先按 Teleopit 官方 standalone standing 流程在支撑架上验证 G1。
- 再验证身体链路，不启用手写入。
- 最后启用 RH56E2；从低速、无负载、短时会话开始。
- 实测并记录 PICO 时间戳到 G1/手动作的端到端延迟、抖动、丢帧和停机行为。

只有 A–E 全部通过，才能把具体硬件组合标记为“可用于真机控制”。

## 立即停止条件

出现以下任一情况立即停止并断开运动使能：故障位非零、温度持续上升或超过限制、电流异常、机械卡滞、网络重复超时、左右手串址、G1 失稳、急停不可用、操作者失去 PICO 跟踪或现场人员进入运动范围。
