# Teleopit RH56E2 Turnkey Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Turn this pinned Teleopit/somehand overlay into a reproducible simulation setup and a guarded RH56E2 Modbus TCP sim-to-real path with verifiable installation and preflight checks.

**Architecture:** Keep Teleopit and somehand pinned, install this repository as an overlay, and register an RH56E2 hand driver in Teleopit's existing sim2real hand worker. The driver uses a stdlib-only Modbus TCP client, maps somehand radians to the six E2 hardware channels using the Unitree Inspire convention, and separates read-only preflight from explicitly enabled writes.

**Tech Stack:** Python 3.10+, Bash, Teleopit v0.5.0, somehand v0.3.0, pico-bridge v0.2.1, MuJoCo, Modbus TCP.

**Spec:** `README.md`, the supplied RH56E2 V1.0.1 manual, and `docs/真机控制检查.md` define the supported workflow and acceptance boundary.

## Global Constraints

- Never write to a hand during installation or default preflight.
- Require explicit `write_enabled=true` before hardware motion.
- Preserve upstream pins and retain the original Teleopit entry points.
- Use the E2 channel order `pinky, ring, middle, index, thumb_bend, thumb_rotation`.
- Reject active faults, excessive temperature, malformed responses, stale hand tracking, and duplicate dual-hand endpoints.
- Treat source review as static evidence; do not claim hardware verification without a bench test.
